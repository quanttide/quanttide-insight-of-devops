# 发布阶段 — 巡视记录

> 巡视日期：2026-07-07

## 矛盾

正式版发布时，工具以最新预发布 tag 为比较基准，而不是上一个正式版。这不是一个实现 bug，而是一个设计假设的体现：**工具假设每次发布之间都有新提交**。但正式版发布恰恰是例外——它是在预发布系列无新提交时做的阶段晋级。

更深层的问题是：预发布周期的所有变更（alpha→beta→rc）已经被 CHANGELOG 记录过，git log 只是这些内容的原材料。**正式版 CHANGELOG 的内容来源应该是预发布 CHANGELOG 条目，而不是 git log。**

## 本质

- 工具擅长"增量"——在有新提交时正确工作
- 正式版发布是"汇总"——需要合并已有信息，而非产生新信息
- 两种场景需要的输入不同，但当前工具只用一种输入（git log）

## 追问

- 是否所有"阶段晋级"（alpha→beta→rc→正式）都应该从已有 CHANGELOG 汇总，而不是从 git log 生成？
- 如果答案是肯定的，那 `collect_git_log` 的定位是否需要重新思考——它只在有真正新提交的增量发布中有意义？
